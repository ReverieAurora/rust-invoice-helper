# Rust 发票小助手

面向 64 位 Windows 10/11 的本地离线 PDF 发票整理工具。程序不调用大模型，不上传文件，也不会移动、重命名或删除源 PDF。

## v0.3.2hotfix 功能

- 双击 EXE 后进入轻量内联 TUI，可选择模式和 PDF 来源目录，并实时查看处理进度；不会占满终端或清除滚动历史。
- 只扫描来源目录第一层的 PDF，单份文件解析崩溃或超时不会带崩整批任务。
- 根据电脑逻辑核心数有限并行处理 PDF，最多同时处理 8 份；结果仍按原文件顺序汇总和导出。
- 从文件名兼容空格、下划线、短横线等分隔符提取提交人，同时支持“姓名 + 物品 + 金额”和“姓名 + 金额 + 物品”；金额可带“元/圆”和货币符号，中文姓名紧接英文物品名时也可识别。
- 文件名金额会与发票正文价税合计核对；结构或金额不符合规则时进入 `错误_文件名格式错误`，文件名结构正确但姓名仍无法判断时才进入 `错误_提交人无法识别`。
- 校验购买方名称“广东工业大学”和税号 `12440000455860226X`。
- 红冲发票（全额或部分）、字段缺失和存在明确 PDF 转换风险的发票进入对应待核查目录。
- 文件名符合发票规则但没有文字层的图片转换PDF进入 `错误_PDF疑似非原文件`；只有文件名和内容都缺少发票信号时才进入 `非发票PDF`。
- 按销售方精确名称汇总有效发票，累计金额 **大于等于 1000.00 元** 标记为超1k公司。
- 玩具类发票单独分类，但仍参与销售方与提交人统计。
- 普通有效发票默认每 30 张分入连续的 `发票_01`、`发票_02`；可在 TUI 中设置任意上限，设为 0 时不限制并全部放入 `发票_01`。超1k发票按提交人建立子目录。
- TUI 默认开启自动日志：处理成功后，日志会保存到本次生成的处理结果目录；如果在结果目录生成前处理失败，则回退保存到所选 PDF 来源文件夹。可在设置页通过上下菜单关闭或重新开启；关闭后日志只在内存中暂存，不会自动写入电脑。
- 根据实际内容按需生成最多四份 Excel，不会创建只有表头的空表；Markdown 处理报告始终生成，便于人和 AI 阅读。

完整模式的结果目录包含：

```text
发票处理结果_时间戳/
├─ 发票_01/、发票_02/……（按用户设置的上限自动分批）
├─ 玩具类发票/
├─ 非发票PDF/
├─ 错误_*/
├─ 汇总表.xlsx（存在处理记录时）
├─ 个人开票金额统计.xlsx（存在有效金额时）
├─ 错误追查表.xlsx（存在错误或非发票记录时）
├─ 支付截图补充表.xlsx（存在超1k销售方发票时）
├─ invoice-helper-时间戳.log
└─ 处理报告.md
```

## TUI 操作

- 主页、设置页、完成页和错误页统一使用 `↑/↓` 选择、`Enter` 确认，不需要记忆字母快捷键。
- 主页包含“开始处理”“选择来源目录”“设置”和“退出”。直接按 `Enter` 选择 PDF 文件夹后即可按默认配置开始。
- “设置”中可依次配置处理模式、分批上限、自动保存日志，以及手动另存当前日志。
- 修改自定义分批上限时需要输入数字并按 `Enter` 保存；输入 `0` 表示不限制。
- 自动日志默认开启并保存到本次处理结果中；处理失败且没有结果目录时回退到 PDF 来源文件夹。同一次程序运行中会记住开关状态。
- 完成或出错后，同样通过上下菜单选择退出、返回重新处理或手动另存日志。

处理期间会显示当前文件、总文件数和进度条。

运行日志包含程序版本、运行环境、处理模式、来源路径、分批设置、并行数、总耗时和汇总结果；每份 PDF 还会记录文件名、大小、SHA-256、处理耗时、识别状态、提交人、文件名金额与正文金额的核对结果、发票关键字段、PDF 风险、主要错误、分类目录、全部具体原因及对应建议操作。仅获得日志时也可以据此定位问题并判断下一步处理方式。日志不保存 PDF 完整正文。自动日志使用不重复的时间戳文件名，避免覆盖旧日志；也可从设置页、完成页或错误页的菜单中手动另存当前会话快照。

## 使用

双击 `invoice-helper.exe` 后进入轻量内联 TUI，默认选择“完整校验、分类与 Excel 导出”。最简单的操作是直接按 `Enter`，选中 PDF 来源目录后程序会自动开始；结果会生成在所选目录中。

也可以运行快速汇总模式：

```powershell
.\invoice-helper.exe "D:\发票目录"
```

指定 Markdown 报告路径：

```powershell
.\invoice-helper.exe "D:\发票目录" --output "D:\结果\发票汇总.md"
```

命令行运行完整模式（`--output` 指定结果父目录）：

```powershell
.\invoice-helper.exe "D:\发票目录" --full --output "D:\结果"
```

完整模式下自定义每个发票文件夹最多放 50 张：

```powershell
.\invoice-helper.exe "D:\发票目录" --full --max-files-per-folder 50
```

不限制数量，所有普通有效发票放入同一个 `发票_01`：

```powershell
.\invoice-helper.exe "D:\发票目录" --full --max-files-per-folder 0
```

## 边界

- 当前针对带文字层的电子发票，不包含 OCR；扫描图片发票会进入待核查目录。
- “PDF 原文件”无法仅靠离线静态检查绝对鉴真。程序只在发现明确转换工具或结构风险时标记“PDF 疑似非原文件”，最终仍需人工核验。
- 销售方名称完全相同才合并，不会自动合并相似名称。

## 从源码构建

安装 Rust stable 后运行：

```powershell
cargo test
cargo build --release
```

生成文件位于 `target\release\invoice-helper.exe`。Release 配置使用静态 MSVC CRT，正常 64 位 Windows 10/11 无需另外安装 Rust。
